* flexiv-steward

~fs~ is a small command-line helper for repeatable Flexiv worktree, build,
test, and agent-handoff workflows.

#+begin_src sh
fs --project ~/ws/flexiv_sw/v4.x_develop context
fs context --json
fs wt doctor
fs wt list
fs wt add task/SW-123-fix-thing from origin/release/v4.2
fs wt switch task-SW-123-fix-thing
fs wt rm task-SW-123-fix-thing
fs wt sync RemoveSync2 --dry-run
fs deps doctor --strict
fs preset list
fs preset current
fs preset use ubuntu-relwithdebinfo-g1
fs preset clear
fs setup
fs setup ubuntu-relwithdebinfo-g1 --dry-run
fs gc builds --dry-run
fs gc builds
fs build --target RobotControlApp
fs build ubuntu-relwithdebinfo-g1 --configure
fs build ubuntu-static-check --configure --target FlexivSwClangTidyCheck
fs test workflow --dry-run
fs run uiapp
fs run rca --dry-run
fs session handoff --days 3
#+end_src

All read-only commands discover the enclosing Git worktree, or a bare hub, by
default. Use
~--project~ to operate on a different worktree explicitly.

~fs session handoff~ reads local Codex, OpenCode, Cursor, and Copilot records
only for the selected worktree. It prints a bounded, redacted summary; it never
uploads transcripts or writes them into the repository.

~fs wt sync~ refuses dirty worktrees, fetches the base ref, and merges it. If
Git reports conflicts, it leaves the merge in place and prints the conflicted
files plus the commands to resolve or abort it.

~fs wt doctor~ reports each worktree's last active time using its latest HEAD
reflog entry or newer uncommitted-file modification. It does not traverse
ignored build outputs.

~fs wt list~ shows every worktree with its checked-out branch and parent branch.
The parent is the branch's upstream when it has one, otherwise the branch it was
created from as recorded in its reflog. The enclosing worktree is marked with
~*~, worktrees whose directory was deleted are marked ~(prunable)~, and ~--json~
emits the same data for tools. Use ~fs wt rm <worktree>~ to prune a prunable
entry.

~fs wt add <branch> from <parent>~ ensures a worktree exists for ~<branch>~
under the workspace root (folder name is the branch with ~/~ replaced by ~-~)
and prints exactly one path on stdout. Exit codes: 0 when it created, attached,
or adopted the worktree, 3 when it already existed, 4 when it refused, 2 for
usage errors. Notes go to stderr.

- New branch: fetches ~<parent>~ and creates ~<branch>~ from it.
- Local branch exists: skips the fetch, attaches a worktree at the branch tip,
  and warns unless ~<parent>~ is already the branch's upstream.
- Only ~origin/<branch>~ exists: fetches it, creates a tracking local branch
  from the remote tip, and reports the adopted commit on stderr.
- Registered worktree exists: prints its path and exits 3 without touching it.
- The registration is prunable or locked: refuses with a hint to run
  ~fs wt rm <branch>~ first.
- The destination folder is taken: refuses and names the occupant.

This makes ~fs wt add~ safe to rerun. Run ~fs --project <path> preset list~ to choose a configure preset, then
~fs --project <path> setup~ to initialize submodules and configure the
remembered or most-used preset, or name one with
~fs --project <path> setup <preset>~.

~fs wt rm <worktree>~ asks for confirmation, deletes the worktree directory
including submodule checkouts, then runs ~git worktree prune~. Locked worktrees
are unlocked first, the branch is kept, and the main or current worktree is
never removed.

~fs wt switch <worktree>~ prints the worktree's absolute path. A program cannot
change its parent shell's directory, so this only cds when the ~fs~ shell
wrapper from the [[*Shell integration][Shell integration]] section is installed.
Without the wrapper, use ~cd "$(fs wt switch task-SW-123-fix-thing)"~.

~fs deps doctor~ compares direct external repositories (including
~external/proto~) with the ~GIT_TAG~ declared in the top-level CMake project,
and checks every recursive Git submodule. Use ~--strict~ in an agent or build
preflight to fail on missing or mismatched revisions. ~fs build~ runs the same
version check by default; ~--skip-deps-check~ is an explicit escape hatch. Add
~--verbose~ to list every clean dependency revision.

For a newly created worktree, use ~fs preset list~ to inspect the checkout's
CMake presets, then ~fs setup~. It initializes recursive submodules, runs CMake
configure so declared externals are checked out, and then verifies all
dependency revisions.

~fs setup~ takes an optional configure preset. An explicit
~fs setup <configure-preset>~ wins. Without one, Steward reuses the worktree's
remembered preset from ~<worktree>/.steward/preset.json~, otherwise the most
frequently used configure preset in ~<workspace>/.steward/preset_history.json~.
The workspace is the bare hub or the primary worktree, so ~fs setup~ run in
~$HOME/ws/flexiv_sw/xxx~ reads
~$HOME/ws/flexiv_sw/.steward/preset_history.json~. Stale history entries are
skipped with a note on stderr. A successful setup records the chosen preset in
the worktree and counts the use for later runs.

Submodule objects are cached below the superproject's common Git directory at
~flexiv-steward/submodules-v2~. Caches are keyed by remote URL, contain only
the exact commits pinned by the superproject, and are prefetched concurrently.
They survive linked-worktree removal; warm setup therefore works entirely from
the local cache without depending on a long-lived checkout.

~fs setup~ applies the same strategy to every ~FlexivAddExternal~ project
declared by the top-level ~CMakeLists.txt~. Exact commits are fetched once into
~flexiv-steward/externals-v1~ below the common Git directory, then each worktree
gets a shallow clone from that cache with ~origin~ restored to the real URL.
First-time setup still needs the network; later worktrees and version bumps
reuse the cache, and submodules inside an external are initialized from the
submodule cache as well. Only top-level declarations are cached; repositories
that declare further externals themselves are left to CMake.

~fs gc builds~ deletes build and install artifacts from every other worktree
in the same Git repository, regardless of age, dirty state, or worktree lock.
It preserves the enclosing worktree (or the one selected with ~--project~).
It removes ~build/~, ~install/~, ~build_yocto/~, and ~cmake-build-*/~ directories
at the worktree root and, for wrapper layouts, under ~flexiv/~.
Symlinked roots are skipped, and directories containing tracked files or another
worktree are refused. Source files and external install locations are preserved.
Use ~fs gc builds --dry-run~ to preview the paths and ~--json~ for machine-readable
results. Both preview and cleanup display each directory's disk usage and the
total, measured before deletion. JSON includes ~size_bytes~ keyed by directory
path and ~total_bytes~.

~fs gc worktrees --base origin/main~ previews linked worktrees whose HEAD is
contained in the specified base ref, whose last activity is at least 30 days
old, and whose working tree has no tracked, untracked, or ignored changes.
Use ~--older-than DAYS~ to change the age threshold, ~--json~ for a machine
readable inventory, and ~--apply~ to remove eligible worktrees. The command
keeps the current and main worktrees, locked or detached worktrees, and local
branches. It rechecks each candidate before removal and never uses Git's
~--force~ option. Worktrees with initialized submodules are listed but skipped
because Git requires force to remove them. Run ~git fetch --prune~ first if the base is a remote ref;
the command does not fetch. Squash and rebase PR merges are not inferred from
local ancestry, so those worktrees remain for manual review.

* Shell integration

Shell completion uses
[[https://kislyuk.github.io/argcomplete/][argcomplete]] and covers subcommands,
worktree names/branches for ~wt rm~, ~wt switch~, and ~wt sync~, and branch refs
for ~wt add ... from <ref>~ and ~wt sync --base~. Register it once:

#+begin_src sh
# bash: add to ~/.bashrc
eval "$(uvx --from argcomplete register-python-argcomplete fs)"

# zsh: add to ~/.zshrc (after compinit)
eval "$(uvx --from argcomplete register-python-argcomplete --shell zsh fs)"
#+end_src

To make ~fs wt switch~ cd in the current shell, add this function below the
completion line (the completion script invokes ~fs~ without arguments, so
tab-completion keeps working through the same function):

#+begin_src sh
fs() {
  local target
  if [[ " $* " == *" wt switch "* ]]; then
    target="$(command fs "$@")" || return $?
    if [[ -d "$target" ]]; then cd "$target"; else printf '%s\n' "$target"; return 1; fi
  else
    command fs "$@"
  fi
}
#+end_src

On TAB, the registered shell function re-runs the real ~fs~ binary with
~_ARGCOMPLETE=1~, ~COMP_LINE~, and ~COMP_POINT~ exported, and reads completions
from file descriptor 8 instead of stdout. ~argcomplete.autocomplete(parser)~
in ~main~ detects that environment, reparses the partial command line, finds
the argument under the cursor, and calls its completer: ~_complete_worktrees~
lists worktree directory basenames and branch names via ~collect_worktree_summaries~,
~_complete_branches~ lists local and remote refs via ~git for-each-ref~. Any
discovery error yields no candidates, so completion never errors mid-typing, and
native argparse ~choices~ (such as the literal ~from~) are completed
automatically. New worktrees appear without reloading the shell.

Development checks use strict mypy:

#+begin_src sh
uv run mypy
uv run python -m unittest discover -s tests -v
#+end_src

See [[file:docs/performance.md][docs/performance.md]] for the measured submodule and
build-directory results.

Both configure and build run through ~docker/docker_dispatch.sh exec <platform>
bash -c~, from the CMake source directory. Steward detects both the ~flexiv_sw~
wrapper layout (source under ~flexiv/~) and a direct ~flexiv_sw_base~ worktree
(source at the repository root). ~fs setup~ and ~fs build~ both take an optional
preset. With ~--configure~, ~fs build~ first configures the
~configurePreset~ named by that build preset. ~fs preset list~ shows both groups,
including names from ~CMakeUserPresets.json~. Use ~--json~ for machine-readable
output. Preset names come from the selected worktree; there is no separate
~all~/~rca~/~ui~ profile mapping.

An explicit ~fs build <build-preset>~ also records that preset and counts its
configure preset, so later runs need no argument. Plain
~fs build --target RobotControlApp~ reuses the remembered build preset, or the
build preset whose ~configurePreset~ matches the remembered configure preset,
and prints the source of that decision on stderr. Build never falls back to the
workspace history: the build preset must correspond to what ~fs setup~
configured, and with nothing remembered it fails with a hint (exit 2).

Both files are local state under ~.steward/~ and are never committed. The
history stores per-preset use counts and last-used times, but it is only a
convenience: a missing or corrupt file is ignored. Steward appends ~.steward/~
to the repository's local ~.git/info/exclude~, so no worktree looks dirty and
~fs wt sync~ and ~fs gc worktrees~ still work. ~--dry-run~ records nothing.
~fs preset current~ and ~fs preset history~ show the recorded state, and
~--json~ emits either for tools.

~fs preset use <configure-or-build-preset>~ remembers a preset for this worktree
without running setup. It accepts either preset kind, writes
~<worktree>/.steward/preset.json~, and counts the configure preset in the
workspace history, so it can influence the next ~fs setup~ default. It reports
the recorded configure preset and, when a different build preset applies, the
build preset ~fs build~ will use. Unknown or hidden names fail with exit 2 and a
~fs preset list~ hint. Tab completion offers configure and build names
together, with the recorded and history-preferred ones first.
~fs preset clear~ removes the remembered file, and its directory when empty. It
only forgets this worktree's local state; the workspace history is untouched,
and it exits 0 whether or not a preset was recorded.

* Running RCA and UIApp

~fs run rca~ and ~fs run uiapp~ use the checkout's ~run_rca_for_ubuntu.sh~ and
~run_ui_for_ubuntu.sh~ to launch existing Linux binaries on the host,
from the build directory so relative ~specs/~ and ~user_data/~ paths work.
The build directory comes from, in order, an explicit
~--preset <configure-preset>~, an explicit ~--build-dir <path>~, the worktree's
remembered configure preset from ~<worktree>/.steward/preset.json~, then the
built-in default ~build/Linux/RelWithDebInfo~ under the detected source tree
(including the wrapper's ~flexiv/~ directory). Relative build paths are
relative to the source tree. Using the remembered preset is noted on stderr:
~Using remembered configure preset '<name>' for the build directory.~ A stale
remembered preset is skipped with
~ignoring stale remembered preset '<name>'~, as is a non-Ubuntu (yocto) one:
~remembered preset '<name>' is not an Ubuntu build; using the default build directory~.
Both fall back to the built-in default. ~--dry-run~ resolves and prints the
full launch without starting the app and records nothing. Building and
configuring remain explicit operations.

#+begin_src sh
fs run uiapp --preset ubuntu-relwithdebinfo-g1-All
fs run uiapp --build-dir build/Linux/Release -- -p ubuntu_pc
fs run uiapp
fs run rca
fs run rca AX01H-06-D1-Yangda
fs run rca AX01H-06-D1-Yangda --dry-run
fs run rca AX01H-06-D1-Yangda -- -c /path/to/custom/flexivCfg.xml
fs run rca -- -G
#+end_src

Pass launch-script arguments after ~--~. The RCA script supplies its normal
configuration, serial number, user data, motion bar, control box, user type and
simulator defaults. A positional serial number sets ~-s~ and infers ~-c~ from
the model before the first dash: ~AX01H-06-D1-Yangda~ selects the selected
build's ~specs/robots/FlexivAX01H/flexivCfg.xml~. The serial's case is preserved;
the model lookup uses uppercase. Missing inferred configs fail before launch
with an explicit ~-c~ override hint. You can still pass ~-s~ and ~-c~ after ~--~.
~-G~ starts the script's debugger mode. UIApp's script supplies
the UI/RCA specs and user-data paths, platform and Qt WebEngine settings.
Steward sets ~flexiv_sw_path~ and ~flexiv_sw_build_path~ to the selected build
directory and resolves ~flexiv_thirdparty2_path~ automatically. This also fixes
the RCA script's default ~specs/~ and ~user_data/~ paths in wrapper checkouts.
If a checkout has no launch script, Steward falls back to invoking the binary;
RCA then needs its full application arguments, and UIApp defaults to ~-p ubuntu_pc~.

RCA serves Modbus TCP on the privileged port 502, so Steward launches it through
~authbind --deep~. ~--deep~ keeps authbind's bind shim across
~run_rca_for_ubuntu.sh~ and every child process it starts. Authorizing that one
port for the current user is a one-time host setup:

#+begin_src sh
sudo apt install authbind
sudo touch /etc/authbind/byport/502
sudo chown "$USER" /etc/authbind/byport/502
sudo chmod 755 /etc/authbind/byport/502
#+end_src

Port 502 is below 512, so authbind expects a plain ~502~ permission file (no
~!~ prefix). Without one, RCA starts but cannot bind the port. ~fs run rca
--no-authbind~ launches directly, for example when running as root or when the
binary already has ~CAP_NET_BIND_SERVICE~. UIApp is never wrapped. ~--dry-run~
still prints the full ~authbind --deep~ command without needing authbind
installed.

Steward uses ~EXTERNAL_ThirdParty2_DIR~ from the selected build's ~CMakeCache.txt~
when it names a host path. For Docker's canonical ~/opt/flexiv_thirdparty2~,
it sources this checkout's ~docker/docker_config.sh~ (including ~local.env~)
to obtain ~FLEXIV_THIRDPARTY2_SHARED_PATH~. It sets the matching Qt library and
plugin paths, MuJoCo library path and thirdparty ~lib/~ path, preserving existing
~LD_LIBRARY_PATH~ entries and the host environment (including display settings).
It does not start Docker or create volumes. Missing runtime files report an
error with a setup hint; Steward never picks an unrelated installed volume.
